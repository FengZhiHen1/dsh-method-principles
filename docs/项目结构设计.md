# dsh-method-principles 项目结构设计

## 权威范围

本文唯一拥有本插件的模块边界、目录组织、依赖方向、命名与全局约定。需求事实归 `需求.md`，技术选型归 `技术栈设计.md`，机制细节归 `technical-details/`。本文不重复定义机制内容。

## 结论先行

- 单包布局，遵循仓库 `core/adapter` 分层约定：本插件为薄壳形态，不设 `src/core/`（无值得裸 node 单测的领域逻辑）。
- 依赖方向单向：`index.js` → `src/adapter/host.js`；adapter 不反向被 core 引用（无 core）。
- 包名 `dsh-method-principles`；插件行 id `method-principles`；段名 `deployment:method-principles`——三者刻意不同层级，不互相推导。

## 目录结构

```text
plugins/dsh-method-principles/          # submodule（remote: FengZhiHen1/dsh-method-principles）
├── package.json                        # name/version/type/main/exports/files + dsh.bundle
├── cordis.patch.yml                    # bundle 层：一行 insert
├── index.js                            # 薄转发入口（唯一导出面）
├── src/
│   └── adapter/
│       └── host.js                     # Config schema + 段注册 + 默认文案常量
├── test/
│   ├── config.test.mjs                 # 配置解析
│   ├── section.test.mjs                # 段注册契约
│   ├── lifecycle.test.mjs              # 挂载→卸载→重挂
│   └── composition.test.mjs            # cordis.patch.yml 过 Loader 的组合断言
├── docs/                               # 本设计目录
└── README.md                           # 安装、配置与用法（面向使用者）
```

不创建 `src/core/`、不创建 `src/client/`、不创建 `design/`、不创建 `verify/`（测试规模不需要独立验证脚本）。

## 模块职责与边界

| 模块 | 职责 | 不允许的依赖 |
|---|---|---|
| `index.js` | 从 `src/adapter/host.js` 重导出插件面（`name`/`inject`/`Config`/`apply`）；不承载逻辑 | 不 import 其他插件、不访问文件系统 |
| `src/adapter/host.js` | 声明 `Config` schema 与默认文案常量；`apply` 中注册/注销提示词段 | 不 import `@deepseek-ai/cordis`；不提供 Service；不注册工具 |
| `test/*.mjs` | 验证配置、段契约、生命周期、组合 | 不 boot 完整 DSH、不访问网络 |

- 依赖方向：`test` → `index.js` → `src/adapter/host.js`，无环。
- 分层门禁：`node tools/plugin-layering-check.mjs plugins/dsh-method-principles` 因无 `src/core/` 走薄壳豁免，输出"通过（无 core，薄壳豁免）"。

## 命名与全局约定

| 名称 | 值 | 约定 |
|---|---|---|
| 包名（`package.json.name`） | `dsh-method-principles` | `cordis.patch.yml` 的 `name` 与之一致；Node 模块解析到 profile `node_modules` |
| 插件行 id（patch `id`） | `method-principles` | 同层唯一；用户覆盖 config 时按此 id 定位 |
| 插件 `name` 导出 | `dsh-method-principles` | 与包名一致，便于 `N entries did not activate` 输出定位 |
| 段名（`section.name`） | `deployment:method-principles` | 全局唯一，自成一格；禁止与 `deployment:persona` 或其他段同名 |
| 段 order | `200` | 自取唯一数值，落在 `deployment:persona`(0) 与 `plan:policy`(500) 之间 |
| 配置字段 | `Config.text` | 单个字符串字段，默认值为默认文案常量 |

- 包 `exports` 只需 `.` 与 `./package.json`；不导出 `./client`。
- `files` 精确列出 `index.js`、`src/`、`cordis.patch.yml`、`README.md`——tarball 缺文件等于安装后缺模块。
- 依赖声明纪律（哪些包进 `dependencies`、哪些进 peer）归 `技术栈设计.md`，本文只规定依赖方向。

## 配置形态

插件行不带 config 时由 schema 填默认值；用户在自己的 patch 层按 id `method-principles` 覆盖。字段只有一个：`Config.text`（字符串）。覆盖语义与关闭语义归 `technical-details/提示词段机制.md`，本文不重复。
