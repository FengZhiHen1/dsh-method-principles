# dsh-method-principles 项目结构设计

## 权威范围

本文唯一拥有本插件的模块边界、目录组织、依赖方向、命名与全局约定。需求事实归 `需求.md`，技术选型归 `技术栈设计.md`，机制细节归 `technical-details/`。本文不重复定义机制内容。

## 结论先行

- 单包布局，遵循仓库 `core/adapter` 分层约定：`src/core/routes.js` 承载纯路由判定（可裸 node 单测），`src/adapter/host.js` 承载 DSH 接线。
- 依赖方向单向：`index.js` → `src/adapter/host.js` → `src/core/routes.js`；core 不 import 任何 `@deepseek-ai/*`。
- 包名 `dsh-method-principles`；插件行 id `method-principles`；段名 `deployment:method-principles`——三者刻意不同层级，不互相推导。

不创建 `src/client/`、不创建 `design/`。

## 模块职责与边界

| 模块 | 职责 | 不允许的依赖 |
|---|---|---|
| `index.js` | 重导出插件面、段常量与纯路由函数；不承载逻辑 | 不 import 其他插件、不访问文件系统 |
| `src/core/routes.js` | 路由匹配（preset 列表、首条命中）、子代理排除、委派深度读取 | 不 import `@deepseek-ai/*`；不接触 ctx |
| `src/adapter/host.js` | 声明 `Config` schema 与默认文案；从装配上下文提取 preset id 与深度；注册/注销提示词段 | 不提供 Service；不注册工具；不直接读 `session.header.agentPreset`（可能过期） |
| `test/*.mjs` | 验证配置、段契约、路由、生命周期、组合 | 不 boot 完整 DSH、不访问网络 |

- 依赖方向：`test` → `index.js` → `src/adapter/host.js` → `src/core/routes.js`，无环。
- 分层门禁：`node tools/plugin-layering-check.mjs plugins/dsh-method-principles` 报"core 文件 1 个"，且无 R1/R2 违规。

## 命名与全局约定

| 名称 | 值 | 约定 |
|---|---|---|
| 包名（`package.json.name`） | `dsh-method-principles` | `cordis.patch.yml` 的 `name` 与之一致；Node 模块解析到 profile `node_modules` |
| 插件行 id（patch `id`） | `method-principles` | 同层唯一；用户覆盖 config 时按此 id 定位 |
| 插件 `name` 导出 | `dsh-method-principles` | 与包名一致，便于 `N entries did not activate` 输出定位 |
| 段名（`section.name`） | `deployment:method-principles` | 全局唯一，自成一格；禁止与 `deployment:persona` 或其他段同名 |
| 段 order | `200` | 自取唯一数值，落在 `deployment:persona`(0) 与 `plan:policy`(500) 之间 |
| 配置字段 | `Config.text`、`Config.routes` | `text` 为基础文案；`routes` 为按 preset 的附加文案列表 |
| 路由 id（`routes[].id`） | 自定义字符串 | 仅用于配置可读性，不参与匹配 |

- 包 `exports` 只需 `.` 与 `./package.json`；不导出 `./client`。
- `files` 精确列出 `index.js`、`src/`、`cordis.patch.yml`、`README.md`——tarball 缺文件等于安装后缺模块。
- 依赖声明纪律（哪些包进 `dependencies`、哪些进 peer）归 `技术栈设计.md`，本文只规定依赖方向。

## 配置形态

插件行不带 config 时由 schema 填默认值（基础文案 + 空路由列表）；用户在自己的 patch 层按 id `method-principles` 覆盖。字段：`Config.text`（字符串）与 `Config.routes`（数组）。覆盖语义、路由匹配规则与关闭语义归 `technical-details/提示词段机制.md`，本文不重复。
