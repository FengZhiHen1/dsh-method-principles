# DSR-001：交付形态——Host bundle 全局提示词段

## 一行式速览

- **决定**：以 Host bundle 插件注册全局系统提示词段交付，对全部 agent 生效。
- **理由**：原则应对所有 agent 与所有工作区生效，且不依赖 preset 选择或工作区指令文件是否在场。
- **被否决项**：preset 级插件行（覆盖不全、无 bundle 可挂）；仅改 `AGENTS.md`（只对带该文件的工作区生效）。

## 上下文

用户要求"给 dsh 追加一段原则提示词"。DSH 提供三条可用通道：① Host bundle 插件注册全局提示词段；② Agent preset 行内插件注册 scoped 段；③ 工作区 `AGENTS.md`（由 `dsh-agent-instructions` 每轮以 user-role 工作区指令注入）。

三条通道的覆盖范围与部署代价不同：通道 ③ 零代码、立即生效，但只覆盖带 `AGENTS.md` 的工作区；通道 ② 改完重启即生效、无需发布门禁，但只覆盖挂载它的 preset；通道 ① 覆盖全部 agent（含子代理），但需走 test 实测门禁、以 `github:` 依赖挂 web，并由用户在 GUI 重启实例才生效。

## 真实方向与评价

| 方向 | 覆盖范围 | 部署代价 | 评价 |
|---|---|---|---|
| A. Host bundle 全局段 | 全部 agent、全部工作区、全部 preset | 高：test 实测门禁 + git 依赖挂 web + 用户重启 | 与"给 dsh 追加"的语义一致 |
| B. preset 级插件行 | 仅该 preset 的 agent 与子代理 | 低：改完重启即生效，不触发发布门禁 | 覆盖不全；未加入该 preset 的 agent 看不到 |
| C. 仅改工作区 `AGENTS.md` | 仅带该文件的工作区 | 零代码、立即生效 | 只对单个工作区生效，不是"给 dsh 追加" |

评价维度以"覆盖范围"与"部署代价"为主。A 在覆盖范围上占优，代价是一次性部署动作；B、C 在部署代价上占优，但覆盖范围明显不足。用户表述为"给 dsh 追加"，指向的是宿主级能力而非单个 preset 或单个工作区。

## 最终决定

采用方向 A：以 Host bundle 插件注册全局段，段名 `deployment:method-principles`，对全部 agent（含子代理）生效。

理由：用户的诉求是宿主级能力（"给 dsh 追加"），只有全局段同时满足"不依赖 preset 选择"与"不依赖工作区文件是否在场"；一次性部署代价换取的是覆盖范围上的决定性优势。

## 直接后果

- 部署必须走两条通道：试验环境源码直挂实测（门禁）→ 稳定环境发布物挂载。
- 生效需要重启实例，且重启由用户在 GUI 执行；插件不得自行重启任何运行中的实例。
- 插件进入稳定环境 profile 的 bundle 集合，卸载需走 `dsh plugin --profile <name> remove`。
- `AGENTS.md` 与工作区指令不受本插件影响；两者可并存（本插件的默认文案自足，不依赖工作区指令）。

波及文档：`../需求.md`（R-04/R-12、AC-04/AC-12）、`../技术栈设计.md`（部署目标）、`../technical-details/部署.md`（部署通道与门禁）。

## 重访条件

- 用户希望只在特定 preset 生效（届时改为 preset 行交付，同时需处理已挂稳定环境的 bundle 卸载）。
- DSH 提供宿主级"工作区无关的用户指令"通道，且覆盖范围等价而部署代价更低时。
