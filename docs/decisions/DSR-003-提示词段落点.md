# DSR-003：落点——注册提示词段，不监听装配事件

## 一行式速览

- **决定**：在 `apply` 中调用一次 `ctx.systemPrompt.section()` 注册独立段。
- **理由**：官方注册面最小、随 fiber 自动回收、与原生段互不干扰。
- **被否决项**：监听 `system-prompt/assemble` 改写整体装配（需自行保留 PTC 协议，脆）；改写 `deployment:persona`（遮蔽部署 persona，且与 registry 自身注册冲突）。

## 上下文

把文案送进系统提示词有三条实现路径：注册新段、在装配 waterfall 中改写整体结果、复用 `deployment:persona` 段。DSH 的段注册会按 order 排序并与原生段拼接；`deployment:persona` 是 deployment 级槽位，preset 会以同名段遮蔽它；`system-prompt/assemble` 是 waterfall，返回值为最终结果，替换方须自行保留 PTC mode 协议。

## 真实方向与评价

| 方向 | 与原生段关系 | 失败面 | 评价 |
|---|---|---|---|
| A. 注册独立段 | 并列拼接，互不干扰 | 段名冲突 / 变量未注册 | 最小概念、官方路径 |
| B. 监听 `system-prompt/assemble` | 替换整体装配 | 需自行保留 PTC 协议；与其他监听器顺序耦合 | 脆，且不必要 |
| C. 复用 `deployment:persona` | 遮蔽 deployment persona | 与 registry 自身注册冲突；preset 会遮蔽它 | 语义错误 |

评价维度：概念与认知成本、失败面、与现有架构契合度。A 只新增一个概念（一个段），副作用随 `ctx.effect` 自动回收，且不依赖其他插件的装配行为。B 把"整个提示词的正确性"变成本插件的责任，代价与收益不匹配。C 与 DSH 的 persona 槽位语义冲突，明确不可行。

## 最终决定

采用方向 A：`ctx.effect(() => ctx.systemPrompt.section({ name: 'deployment:method-principles', order: 200, text }))`；不设 `complete`，不注册 context / variable / tools。

## 直接后果

- 段的可见范围与回收完全由 DSH 的 scope 与 fiber 语义决定；插件无需自管理生命周期。
- 段名必须全局唯一：同层重名会挂载失败，跨 scope 重名会被遮蔽。
- 文案成为静态字符串，不能按 scope 变化；如需按 agent 差异化，须另开决策。

波及文档：`../需求.md`（R-02/R-05、AC-02/AC-05）、`../项目结构设计.md`（命名与全局约定）、`../technical-details/提示词段机制.md`（段契约、装配位置、失败语义）。

## 重访条件

- 需要按 scope 或按 agent 差异化文案（届时评估 scoped 段注册）。
- DSH 的 `section()` 契约发生变化（如新增段级别名或优先级机制）。
