# DSR-005：基础段收敛——8 条 → 4 条证据诚实底线

## 一行式速览

- **决定**：基础段由附图 8 条收敛为 4 条（成功标准 / 不确定性披露 / 观察与推测分离 / 消融），标题改为 `Evidence discipline:`。
- **理由**：原 8 条里有条目与工程层**在同一提示词内自相矛盾**（无条件"命名根因"），有条目抵消工程层的刻意排除（对抗式审查），其余则由工作区指令、结构门禁或工程层覆盖。
- **被否决项**：保持 8 条不动（矛盾与冗余保留）；直接取消基础段（三格 agent 失去唯一方法论层）。

## 上下文

最初的设计基线是"自洽 8 条"（需求 R-06/AC-06），依据是"插件对任何工作区自足"。此后两件事推翻了它的前提：

1. **工程层改版确立了新判据**：接受评审意见后，工程层把"命名根因"改成**条件式要求**，理由是**无条件陈述会诱导模型把猜测包装成已确认根因**。而基础段仍保留原无条件表述——两条文本同时进入编码主 Agent 的提示词，形成互相抵消的指令。
2. **基础段是全局的，因此抵消了工程层的排除**：对抗式审查被工程层刻意排除（`test/config.test.mjs` 有断言），但它仍从基础段发给同一个 agent。

此外逐条复核发现，原 8 条中 ④奥卡姆与 ⑧高内聚低耦合在本仓库已由 `AGENTS.md` 行为准则与分层门禁承载，⑥独立思考只在"比较其他 agent 结论"时触发。

## 真实方向与评价

| 方向 | 矛盾 | 冗余 | 覆盖面 | 评价 |
|---|---|---|---|---|
| A. 保持 8 条 | 有（根因表述） | 高（①⑤⑦与工程层重复、④⑧与门禁重复） | 全 | 保留缺陷 |
| B. 取消基础段 | 无 | 无 | `explore`/`auteur`/子代理三格失去唯一方法论层 | 最省但放弃原始意图 |
| C. 收敛为 4 条 | 无 | 低 | 全（三格仍有底线） | 兼顾 |

评价维度：内部一致性、与既有层的重叠、覆盖面、维护成本。C 在一致性上决定性占优——A 的缺陷不是"多写了几句"，而是**同一提示词里两条规则互相打脸**，这会让模型在"命名根因"与"不确定就说不确定"之间无依据地取舍。

## 最终决定

采用方向 C，逐条处置：

| 附图原则 | 处置 | 理由 |
|---|---|---|
| ① 第一性原理 | 拆分：留"成功标准"，删"先复现"与"命名根因" | 后半与工程层条件式规则矛盾；"先复现"是编码形态，非通用 |
| ② 对抗式审查 | 删 | 基础层是全局的，留着等于把工程层刻意排除的协议送回编码 agent |
| ③ 消融实验 | 保留 | 唯一与其他层不重叠的方法条目 |
| ④ 奥卡姆剃刀 | 删 | 已有工作区指令与结构门禁 |
| ⑤ 列出不自信的点 | 保留 | 对所有 agent、所有任务成立 |
| ⑥ 保持独立思考 | 删 | 触发场景极窄 |
| ⑦ 批判性思维 | 保留 | 对所有 agent 成立，直击幻觉 |
| ⑧ 高内聚低耦合 | 删 | 编码专属且已有分层门禁 |

标题从 `Working principles:` 改为 `Evidence discipline:`，使两层职责在提示词里可区分（基础层=证据诚实，工程层=交付纪律）。

## 直接后果

- 基础段由 9 行降为 5 行（标题 + 4 条），常驻成本下降。
- 被删条目中"根因"部分由工程层承担；对抗式审查按用户决定**不再出现在任何层**（若日后需要，应显式加进工程层，而非借基础层送回）。
- 新增两条回归断言：基础段不得含 `root cause`，两层标题不得相同——防止矛盾类缺陷复发。
- 三层职责固定为：基础层（所有 agent）/ 工程层（编码主 Agent）/ 工作区与门禁（结构纪律）。

## 重访条件

- 需要给**非编码 agent**更强的方法论层（例如 `explore`/`auteur` 也需要基线或复现纪律）：应为其**新增专属路由**，不得把条目退回基础层——否则矛盾类缺陷会随覆盖面一起回来。
- 若日后要恢复对抗式审查：加入工程层（触发式），并同时评估"编码 agent 是否真的会派审查者"，而不是靠基础层。
- 出现新的消融证据表明基础段整体无效果：直接走方向 B（取消基础段）。
