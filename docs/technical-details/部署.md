# 部署

## 权威范围

本文唯一拥有本插件的包形态、部署通道、实测门禁、验证方法与失败排查。需求与验收条件归 `../需求.md`，段机制归 `提示词段机制.md`，选型与版本基线归 `../技术栈设计.md`。本文不定义机制内容。

## 结论先行

- 两个通道：实例 `test` 用 `link:` 源码直挂（实测门禁），实例 `stable-dev` 的 `web` profile 用 `github:` git 依赖（发布物形态）。
- 生效条件：bundle 成员变化**必须重启实例**；web 的重启由用户在 GUI 执行，本插件不自行重启任何实例。
- 实测门禁未通过前不得挂 web。

## 包形态

```text
dsh-method-principles/
├── package.json       # dsh.bundle.patch = "./cordis.patch.yml"
├── cordis.patch.yml   # - insert: [{ id: method-principles, name: dsh-method-principles }]
├── index.js           # 插件面（name / inject / Config / apply）
└── src/adapter/host.js
```

- `dsh.bundle.patch` 指向包内 patch；行 `name` 用包名，禁止源码相对/绝对路径（web 红线）。
- 包进 `dsh.profile.bundles` 即激活其 patch；安装到 `dependencies` 只是可解析，不等于激活。

## 部署通道

以下命令中的 HOME 与 bin 路径是 2026-09-08 现查值，每次部署动作前必须用 `dshl env --json` 重新取值（`instances[].home`、`instances[].version_bin`），不得照抄。

### 通道 A：test 实例（实测门禁）

环境事实（2026-09-08 现查）：实例 `test`，profiles `test`/`web`，未运行。

```powershell
# 0. 取当日事实（每次部署动作前）
node tools/dsh-launcher-cli/cli.mjs env --json

# 1. 源码直挂
$env:DSH_HOME='C:\Users\FengZhiHen\AppData\Roaming\in.dsh-plug.dsh-launcher\homes\test'
node 'C:\Users\FengZhiHen\AppData\Roaming\in.dsh-plug.dsh-launcher\versions\0.1.2-rc.1\node_modules\@deepseek-ai\dsh\lib\bin.js' plugin --profile test add link:E:\Project\DSH_Plugins\plugins\dsh-method-principles

# 2. 组合复查（不启动）
node '…\lib\bin.js' --profile test --dump-config

# 3. 启动实测
node '…\lib\bin.js' --profile test
```

- 报 `ERR_PNPM_UNEXPECTED_STORE` 时追加 `--store-dir=<本机既有 store>`。
- `link:` 直挂会把插件自身 `node_modules` 的依赖一并投影进 profile；本插件仅依赖 Schemastery，投影面无核心服务包。

### 通道 B：web profile（发布物）

```powershell
$env:DSH_HOME='C:\Users\FengZhiHen\AppData\Roaming\in.dsh-plug.dsh-launcher\homes\stable-dev'
node '…\lib\bin.js' plugin --profile web add github:FengZhiHen1/dsh-method-principles#<ref>
```

- 前置条件：子仓库已 commit/push，顶层已提交 gitlink 更新，通道 A 实测通过。
- 首次 `add` 若被 pnpm 拦截 git 依赖的 `prepare`，按 pnpm 提示把包键写入该 profile 的 `pnpm-workspace.yaml` 的 `allowBuilds` 后重试。
- 装完后由**用户在 GUI 重启实例**，插件才生效。

## 实测门禁（挂 web 前必须全过）

1. `--dump-config`：`dsh.profile.bundles` 含 `dsh-method-principles`；行清单恰一行 `id: method-principles` / `name: dsh-method-principles`，来源正确、无重复。
2. 启动：无 `N entries did not activate`，无崩溃。
3. 功能冒烟：新建会话展开系统提示词，确认段内容与位置（见下）。
4. 实测结果写入提交说明。

## 验证方法

| 层次 | 方法 | 判据 |
|---|---|---|
| 包内 | `npm test` | 单元 + 生命周期 + 组合全绿 |
| 组合树 | `--dump-config` | 恰一行、来源正确、无重复 |
| 装配结果 | Web UI 系统提示词折叠行（`SystemPromptRow`） | 段可见且文本逐字一致；位置判据见 AC-03 |
| 子代理 | 在会话中派发一个子代理，展开其系统提示词 | 同样包含该段 |
| 卸载 | 移除插件行后重启（或 test 实例 `remove`） | 段消失、无残留 |

`--dump-config` 只证明组合树，不证明装配结果；装配结果以 Web UI 的系统提示词折叠行为准。

## 失败排查

| 现象 | 原因 | 处置 |
|---|---|---|
| `N entries did not activate` 含 `method-principles` | `systemPrompt` 服务缺失（该 profile 未装载基础 bundle） | 补齐基础 bundle 后重启 |
| `invalid config: … (at text)` | config 传了非字符串 | 修正 config |
| `prompt section "deployment:method-principles" is already registered` | 同一 profile 重复挂载本插件 | 只保留一处 |
| `duplicate loader entry id` | bundle 层与用户 patch 层重复 insert 同一 id | 只保留一处；该错只在启动挂载时报，dump 不报 |
| 装配失败：`unknown prompt variable` | 自定义文案含 `{{...}}` | 移除变量引用 |
| UI 里看不到该段 | 实例未重启（bundle 成员变化未生效）或段被同名段遮蔽 | 重启实例；检查是否有其他段使用同名 |

## 已知限制

- bundle 成员变化必须重启实例，热重载不覆盖该变化。
- 本阶段不发布 npm；`github:` 依赖未钉 ref 时由 lockfile 承载 commit，可接受但建议钉 ref。
- 本插件不自行重启任何运行中的实例；web 生效由用户在 GUI 完成。

## 重访条件

- 需要给他人安装 → 评估 npm registry 发布。
- 需要锁定版本语义 → 在 `github:` 依赖上钉 commit ref，或走 registry 版本。
