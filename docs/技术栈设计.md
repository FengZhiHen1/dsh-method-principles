# dsh-method-principles 技术栈设计

## 权威范围

本文唯一拥有本插件的语言与运行时、框架与关键库、版本基线、部署目标、兼容与安全约束及其选型理由。需求事实归 `需求.md`，模块与目录事实归 `项目结构设计.md`，机制细节归 `technical-details/`。本文不定义机制。

## 结论先行

- 栈极薄：Node ESM + 官方 `Config` schema（Schemastery）+ `ctx.systemPrompt.section()`；无编译步骤、无构建工具、无客户端产物。
- 唯一运行期外部依赖：`@deepseek-ai/schemastery`（放 `dependencies`）；不引入 `cordis` 依赖（插件不 import 它）。
- 版本基线对齐部署运行时 `0.1.2-rc.1`：Schemastery `3.18.2`、Cordis `4.0.2`、DSH 包 `0.1.2-rc.1`。

## 语言与运行时

- Node.js `^22.19.0 || >=24`（与部署树 engines 一致；本机实测 `v24.12.0`）。
- ESM 模块（`"type": "module"`）：DSH 插件行按 Node 模块解析加载，CJS 形态不在支持面内。
- 无编译步骤：直接以 `.js` 交付，`node --check` 作语法门禁；不引入 TypeScript 构建链。

## 框架与关键库

| 依赖 | 用途 | 声明位置 |
|---|---|---|
| `ctx.systemPrompt`（`@deepseek-ai/dsh-system-prompt` 提供的服务） | 注册系统提示词段 | 不声明依赖，用 `export const inject = ['systemPrompt']` 表达 |
| `@deepseek-ai/schemastery` | 声明 `Config` schema，挂载前校验并填默认值 | `dependencies` + `devDependencies`（同版本） |
| `@deepseek-ai/cordis` | 不直接使用 | 不声明 |

不引入其他依赖。文案是常量字符串，无 i18n、无模板引擎、无配置框架。声明位置的理由见「选型理由与重访条件」。

## 部署目标

| 目标 | 通道 | 形态 |
|---|---|---|
| 试验环境（实例 `test`，profile `test`） | 源码直挂 | 重启即生效，用作实测门禁 |
| 稳定环境（实例 `stable-dev`，profile `web`） | 发布物挂载 | 只读快照，需用户重启实例生效 |

- 生效方式：bundle 成员变化**必须重启**；重启由用户在 GUI 执行。
- npm registry 发布不在本阶段范围内。

部署步骤与命令见 `technical-details/部署.md`，本文不重复。

## 兼容与安全约束

- 不提供 Service、不注册工具、不注册动态上下文：插件对 DSH 运行时的唯一影响面是一个提示词段，避免落入"服务定义包双副本"与"preset realm 冲突"两类故障。
- 段名 `deployment:method-principles` 全局唯一；重名会导致挂载失败或被遮蔽（失败语义见 `technical-details/提示词段机制.md`）。
- 不声明 `complete`：多个 complete 段会让整个装配失败。
- 文案禁含 `{{...}}`：未注册变量会让 `renderPrompt` 抛错，导致该 scope 的装配失败。
- 不写文件、不访问网络、不持久化：插件无状态，dispose 后零残留。
- 目标运行环境为 Windows（本机 DSH 部署形态）；插件本身无平台相关代码。

需求侧约束（C-01…C-10）以 `需求.md` 为唯一权威，本文不重复定义。

## 选型理由与重访条件

| 选型 | 当初为何选择 | 什么条件会触发重访 |
|---|---|---|
| Schemastery 放 `dependencies` 而非 peer | 其跨边界身份为 `Symbol.for`，双副本无害；一方包先例充分 | 该库改为 module-local `Symbol()` 作身份键，或部署树出现版本分裂（profile 副本落后于安装树） |
| 不声明 `cordis` 依赖 | 插件不 import cordis 任何导出，`inject` 已表达服务依赖 | 插件开始使用 cordis 类型或工具函数 |
| 无编译步骤、纯 `.js` | 插件只有一个模块，构建链的收益为零 | 文案或逻辑增长到需要类型检查与多文件产物时 |
| 不发布 npm | 单用户本机部署，`github:` 依赖已满足需求且省去 registry 维护 | 需要给他人安装，或需要版本号语义化约束时 |

## 非目标

- 不引入 TypeScript 构建链、不引入测试框架（用 Node 内置 `node:test`）。
- 不引入客户端产物与 `dsh.client` 声明。
- 不做多语言运行时切换、不做文案模板渲染。
